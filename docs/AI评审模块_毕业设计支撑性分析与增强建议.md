# 计划书 AI 智能评审模块 —— 毕业设计支撑性分析与增强建议

| 项 | 内容 |
|---|---|
| 文档定位 | 评估 `docs/AI评审模块_需求规格说明书.md` 作为**毕业设计支撑材料**的充分性，并给出增强方案 |
| 分析对象 | 智能创新创业项目管理系统 · AI 评审模块 |
| 日期 | 2026-09-18 |
| 适用 | 本科 / 硕士毕业设计（两条线分别给出取舍建议） |

---

## 一、结论速览

> **能支撑"系统实现型"毕设的及格线，但撑不起"优秀"。**

原因不在功能多少，而在**文档性质错位**：

| 维度 | 现状 | 毕设要求 |
|---|---|---|
| 文档类型 | SRS（需求规格说明书） | 论文需要「研究问题 → 方法 → 实验 → 结论」的闭环 |
| 回答的问题 | "怎么把功能做**对**" | "怎么证明这个方案**比别人好**" |
| 证据 | 119 个验收用例（功能是否通过） | 需要**效果数据**（准确率、一致率、误差） |
| 创新点 | 工程实现层面的优化 | 需要**可被质疑、可被验证**的方法创新 |

**三句话总结缺什么：**

1. **缺可量化的效果证据** —— 没有任何"AI 评得准/评得稳"的数据。答辩第一个问题就是"你凭什么说它有效"，现在答不上来。
2. **缺"为什么这么设计"的对照实验** —— 文档里满是"建议这么做"，但没有一组实验说明"这么做比我原来的做法好"。这些建议在论文里是**假设**，不是**结论**。
3. **缺论文的第五、六章（关键算法 + 实验）** —— 这两章恰恰是决定成绩档次的部分，而现在完全空白。

**好消息**：这三样都能补，而且**第 2 项的大部分成本已经隐含在现有设计里**——你只是没把它设计成实验。

## 三、致命缺口：三条"论文生存线"

### 3.1 生存线一：人工标注基准集 + 一致性评价实验　【最高优先级】

**问题**：现在整个系统没有任何"效果"数据。你只知道**能不能跑通**，不知道**跑得准不准**。

**要做的事：**

1. **构建金标准（Gold Standard）**
   - 选 30–50 份真实申报书（脱敏处理）
   - 请 2–3 位评委老师**独立**打分（互不商量）
   - 形成标准答案：总分 + 各维度分 + 等级 + 关键问题清单
   - 标注者之间先算一次一致性（如果老师之间都不一致，说明题目本身有歧义，这本身就是一个有价值的讨论点）

2. **计算量化指标**

| 指标 | 说明 | 用途 |
|---|---|---|
| MAE（平均绝对误差） | AI 分与人工分的平均偏差 | 主指标，如"MAE = 6.3 分" |
| Spearman 秩相关 ρ | 排序一致性 | 证明"AI 排出的优劣顺序"和老师一致 |
| Cohen's Kappa κ | 等级（A/B/C/D）一致性 | κ > 0.6 为 substantial，是很有力的结论 |
| 维度级一致率 | 每个维度分别算 | 定位"哪一维度 AI 最不准" |
| 证据幻觉率 | 人工核查编造条数 / 总条数 | 证明证据引用机制有效 |
| 章节识别 F1 | 标题定位的 P/R/F1 | 支撑算法章节 |

**为什么这条最重要**：它是**唯一能证明系统有用的硬证据**，也是答辩老师最爱问的。有了它，你的论文结论就从"我做了个系统"升级为"我做的系统与专家评审的一致性达到 substantial 水平"。

**顺带产出一个创新点**：拿到不一致的样本后，反向分析"AI 在哪类章节偏松/偏紧"，据此调 prompt 与权重，再测一次一致性 → 形成「**数据驱动的评审质量持续优化闭环**」。这个闭环有论文价值，而且几乎零额外开发。

---

### 3.2 生存线二：消融实验 / 对照实验　【证明你的设计选择是对的】

**问题**：文档里每一条"建议"都是**未经证明的断言**。评委一句"你凭什么说三级识别比纯正则好？"就能问住。

**解法**：把设计选择全部转成对照组。这张表**本身就是论文第五章的核心**：

| 编号 | 你的设计 | 对照组（Baseline） | 评价指标 | 预期结论 |
|---|---|---|---|---|
| E1 | 三级章节识别（规则+样式+语义） | ①纯正则 ②纯样式 ③规则+语义 | 标题 P/R/F1 | 三级混合 F1 最高 |
| E2 | Word 自动编号场景 | 依赖文本正则的朴素实现 | 标题召回率 | 朴素实现趋近 0（**关键坑验证**） |
| E3 | Rubric 评分锚点 | 裸提示"请给这一章打 1-10 分" | 重复 5 次的打分方差、与人工 Kappa | 锚点显著降低方差、提升一致性 |
| E4 | 强制证据引用 | 不要求引用原文 | 幻觉率 | 幻觉率显著下降 |
| E5 | 章节二次切分 | 不切分（整章喂） | 长章节打分区分度、失败率、token 成本 | 切分后区分度提升、成本可控 |
| E6 | 合并策略（×0.8 + 最低分×0.2） | 简单算术平均 | 对"差段落"的识别灵敏度 | 加权+最低分修正更敏感 |
| E7 | 低温度 + 结构化输出 | 默认温度 + 自由文本 | JSON 合法率、分数波动 | 前者稳定可复现 |
| E8 | 双模型交叉验证 | 单模型 | 分差与人工不一致率的相关性 | 分差大的样本确实更不可靠 |
| E9 | 反提示注入防护 | 无防护 | 注入攻击下的攻击成功率 | 防护有效 |

**成本提示**：E1、E3、E5、E6 这四组**成本最低、收益最高**，建议至少做完这四组。每组只需要注意点开对照组开关，跑同一批文档对比结果即可——因为你本来就要跑这批文档。

**论文写法**：每张实验结果表配"实验设置 / 结果 / 分析"三段，这是标准的实验章节写法。

### 3.3 生存线三：补上"关键算法设计"章节　【高分关键】

**问题**：现在文档里"三级章节识别""分块合并策略""可解释评分"都只是**功能描述**，没有算法层面的刻画。而论文的**第五章（关键算法）是拉开档次的地方**。

**要补的内容**：把下面三块写成独立的算法小节，每节都要有 **伪代码 + 公式 + 复杂度分析 + 参数说明**。

| 算法 | 需要形式化的内容 |
|---|---|
| **A. 文档章节识别算法** | 特征加权打分公式；层级栈的入栈/出栈判定规则；目录区排除的启发式；置信度定义 |
| **B. 长章节分块与得分合并算法** | 递归切分的边界优先级；重叠窗口参数；`章节分 = 加权均分 × 0.8 + 最低块分 × 0.2` 的推导与参数敏感性分析 |
| **C. 可解释评分与证据回溯算法** | 结构化输出的字段约束；evidence 的字符串回溯匹配与"待核实"标记；分数 clamp 规则 |

**加分写法**：每节末尾加"**时间复杂度**"和"**参数取值依据**"。比如为什么重叠 200–300 token、为什么阈值取 3000–6000——最好用一小段实验说明（阈值扫描曲线），这样"参数不是拍脑袋定的"。

## 四、论文章节覆盖度诊断

| 论文章节 | 现有支撑 | 需要补什么 |
|---|:--:|---|
| 第一章 绪论 | ⬜ 空缺 | 研究背景与意义；国内外研究现状（自动作文评分 AES、LLM 辅助同行评议、长文档理解）；本文主要工作与贡献；论文组织结构 |
| 第二章 相关技术 | ⬜ 空缺 | Apache POI/OOXML 文档结构；LLM 与结构化输出；Map-Reduce 分层评审范式；文本分块与滑动窗口；Kappa/MAE 一致性分析方法 |
| 第三章 需求分析 | ✅ 充分 | 直接复用 SRS 第一至四章；补一张**用例图**（角色 × 用例） |
| 第四章 系统设计 | 🟡 部分 | 已有：流程、状态机、表结构。**需补**：总体架构图、功能模块图、关键**时序图**（评审全链路）、E-R 图、类图 |
| 第五章 关键算法设计 | ⬜ 空缺 | **见 3.3**（这一章决定档次） |
| 第六章 系统实现与实验 | 🟡 部分 | 已有：119 个功能测试用例。**需补**：实验设计（E1–E9）、数据集统计、结果表与图、误差分析、案例展示 |

**缺口分布**：7 章中 **3 章完全空缺、2 章部分**。这是当前最大的风险点——不是功能不够，是**论文写不起来**。

## 五、建议增加的功能（按性价比排序）

> 优先级判断标准：**能不能同时产出"功能"和"论文素材"**。能一鱼两吃的排前面。

### 5.1 强烈建议（论文生存线，建议全做）

#### ① 评审一致性分析看板　★★★★★

- **做什么**：评委在线打分 → 系统自动与 AI 分比对 → 可视化展示 MAE、Kappa、各维度一致率、不一致样本清单
- **为什么**：这是 3.1 生存线的**载体**。没有它，一致性分析只能靠手工 Excel，且无法在答辩现场演示
- **现有基础**：`human_review` 表已有 `ai_score_snapshot` 字段，扩展即可
- **论文用法**：既是系统功能（第六章），又是实验平台（第五章数据来源）
- **工作量**：★★☆

#### ② 申报表结构化字段 ↔ 计划书正文　一致性交叉校验　★★★★★

- **做什么**：系统里 `project` 表已存 `project_intro`、`innovation_points`、`market_demand_analysis`、`key_technology` 等结构化字段。做交叉校验：
  - 申报表写了 3 条创新点，正文只论证了 2 条 → 提示"存在未展开的创新点"
  - 申报表"关键技术"是 A，正文讲的是 B → 提示"前后不一致"
- **为什么是**最有价值的差异化功能：**纯文档评审做不到这件事**，它利用了你系统独有的数据优势。答辩时是极好的创新点陈述
- **工作量**：★☆（字段已有，一次 LLM 比对调用）
- **论文用法**：创新点之一 + 可做小实验（构造不一致样本，测检出率）

#### ③ 双模型交叉验证与不确定性量化　★★★★☆

- **做什么**：同一章节用两个模型各评一次，分差超阈值 → 标记"需人工重点复核"
- **为什么**：把"AI 不确定性"变成**可量化的东西**，是很成熟的研究思路，也直接提升系统可信度
- **论文用法**：创新点之一；实验 E8 直接对应
- **工作量**：★★（多一次调用 + 分差逻辑）

#### ④ 原文溯源高亮　★★★★☆

- **做什么**：报告页点击某条 AI 评语 → 跳转原文对应段落并高亮
- **为什么**：把评委的心态从"我要不要信 AI"变成"我自己能看"。**答辩现场演示效果最好的一项**
- **技术**：`docx-preview` 或把 docx 转 HTML 渲染，配上段落 ID 定位
- **论文用法**：第四章交互设计 + 第六章演示；也可量化"评委核查耗时下降"
- **工作量**：★★★

### 5.2 加分项（工作量充裕时做）

| # | 功能 | 价值 | 工作量 |
|---|---|---|---|
| ⑤ | **相似度 / 原创性检测**（SimHash/MinHash 与库内历史文档比对） | 评审场景刚需，可做成独立小实验（查重检出率） | ★★ |
| ⑥ | **AI 评委追问（RAG 问答）**：就某章节追问"为什么给 3 分" | 基于原文的检索问答，交互性极强 | ★★★ |
| ⑦ | **智能修改助手**：把"修改建议"一键生成改写后的段落草稿 | 直击学生真实痛点，演示亮眼 | ★★★ |
| ⑧ | **Prompt 版本管理与 A/B 对比**：prompt 存库带版本号 | 支撑 E3/E7 实验，让实验可复现 | ★☆ |
| ⑨ | **成本与质量看板**（管理员视角）：token 消耗、耗时、各模型表现 | 体现系统化思考与工程完整性 | ★★ |

### 5.3 锦上添花（有精力再说）

- 评审报告一键导出 PDF（可归档、可打印）
- 立项等级预测（不只给分，直接给"建议立项等级"）
- 与往届已立项项目的**对标差距分析**
- **模型微调（LoRA / DPO）**：用积累的人工修订数据微调 → 这是第七章"未来工作"的优质素材，**建议只写不做的**（写进展望，不必真做）

### 5.4 明确建议**不要**做的

| 不做 | 原因 |
|---|---|
| 恢复 PDF / DOC 全格式支持 | D-01 已论证其性价比低，会吃掉大量时间且拉低章节识别准确率 |
| 自动改写正文并回写 Word 文档 | 风险高、边界多，收益不如做实验 |
| 复杂权限 / 多租户 / 计费 | 与课题无关，纯堆料，答辩不加分 |
| 追求 UI 花哨 | 评委看的是方法与数据，不是皮肤 |

## 六、实验设计清单（可直接抄进论文）

### 6.1 数据集构建

| 项 | 建议 |
|---|---|
| 来源 | 本校历年创新创业申报书（脱敏） |
| 规模 | 本科 30–50 份；硕士 80–150 份 |
| 分层 | 覆盖不同项目类型、不同质量档次（优/中/差均要有）、不同排版风格 |
| 标注 | 章节标题人工标注（用于 E1/E2）；总分与维度分由 2–3 位评委独立标注 |
| 标注一致性 | 先算标注者间 Kappa；若 κ < 0.4 需重新定义评分口径 |
| 论文呈现 | 一张"数据集统计表"：文档数、平均字数、平均章节数、字数分布、项目类型分布 |

### 6.2 实验矩阵

- **主实验**：AI vs 人工 一致性（MAE / Spearman / Kappa / 维度级一致率）
- **消融实验**：E1–E9（见 3.2），逐项开关对照
- **参数敏感性**：分块阈值（2000/4000/6000/8000）对区分度与成本的影响曲线
- **鲁棒性实验**：异常文档（无样式、含目录、加密、伪后缀、含注入指令）下的处理正确率
- **性能实验**：单份文档端到端耗时、token 消耗、并发能力

### 6.3 评价指标定义（论文里要写公式）

| 指标 | 公式要点 |
|---|---|
| Precision / Recall / F1 | 章节标题识别的标准定义 |
| MAE | 平均绝对误差，用于分数偏差 |
| Spearman ρ | 排序相关性 |
| Cohen's Kappa | 等级一致性，附 Landis & Koch 判读标准（>0.6 substantial） |
| 幻觉率 | 人工核查编造的评语条数 / 总评语条数 |
| 一致性覆盖率 | 能回溯命中原文的 evidence 占比 |

1. **文档结构识别**：提出"规则打分 + 样式特征 + 语义兜底"的三级章节识别方法，解决 Word 自动编号导致纯正则失效的问题
2. **可解释评审**：以 Rubric 评分锚点约束打分一致性，并强制证据引用 + 原文回溯校验，把评审从"黑箱打分"变为可核查结论
3. **一致性闭环**：构建 AI 与人工评审的一致性量化方法（MAE/Kappa），并据此反向优化评审策略，形成持续改进闭环

> 这三条的共同点：**每一条都能用一组实验数据支撑**。这是创新点和"功能罗列"的分界线。

## 八、工作量与取舍（两条线）

### 8.1 本科毕设线（推荐）

**保留**：现有 SRS 全部内容

## 九、数据合规提醒（做实验时会放大）

| 风险 | 应对 |
|---|---|
| 申报书是**真实材料**且含个人信息与未公开创意 | 入库前脱敏；论文与答辩中**不贴原文**，用示意性替换文本 |

## 十、建议你先做三件事

如果只能做三件，按这个顺序：

1. **约评委老师，启动标注数据集**（排期最长、最不受控，越早越好）
2. **把设计选择改造成实验开关**（E1/E3/E5/E6 四组），因为你本来就要跑同一批文档，几乎零额外成本
3. **补第五章算法设计**，把三级识别、分块合并、可解释评分写成"伪代码 + 公式 + 复杂度"

做完这三件，论文的**骨架就立起来了**，剩下的开发都是填充。

## 附：一句话回答你最初的问题

> **当前需求文档够不够？** 够做系统，不够写论文。
> **要不要加功能？** 要，但**不是加更多功能，而是加"能证明效果"的功能**——一致性分析看板、交叉校验、双模型验证、原文溯源这四项，加上 4 组消融实验，就能把及格线拉到优秀。
> **最该警惕的**：别陷入"再堆一个功能"的惯性。堆到第 15 个功能，答辩还是会被问"你怎么证明它准"，而那时光阴已经没了。
