# 智能创新创业项目智能评审系统 —— 完整流程设计

> 本文档基于现有系统（学生提交 → 评审人评审）梳理，在**不改变业务流程主干**的前提下，补齐技术层次，形成端到端闭环。作为毕业设计的功能设计与技术实现依据。

---

## 一、系统定位与整体架构

### 1.1 定位升级

| | 原系统 | 目标系统 |
|---|---|---|
| 本质 | 信息管理系统（记录、流转、存档） | 智能决策支持系统 |
| 评审 | 人工逐份阅读 | 多智能体协作评审 + 人工终审 |
| 文档 | 只做上传存储 | 结构化解析、切分、知识化 |
| 数据 | 静态沉淀 | 图谱化、可检索、可洞察 |
| 反馈 | 审完即止 | 数据回流、模型持续进化 |

### 1.2 五层架构

| 层次 | 职责 | 关键模块 |
|---|---|---|
| 前端展现层 | 交互与可视化 | 申报提交、评审看板、辩论可视化、图谱浏览 |
| 应用服务层 | 业务编排与接口 | 接口网关、任务调度、权限、数据持久化 |
| **智能体编排层** | 核心智能逻辑 | 专家 Agent 组、辩论引擎、共识汇总 |
| 能力组件层 | 复用能力 | GraphRAG 检索、文档解析、证据校验、代写检测 |
| 模型与存储层 | 基础支撑 | LLM 服务、向量库、图数据库、MySQL |

## 二、完整流程

### 阶段一：离线准备 —— 知识库与图谱构建

**性质**：一次性执行，后续增量更新。

**输入**：评审细则、操作手册、历年申报书、历年评审记录、获奖记录。

**步骤**：

1. **文档解析**：使用 Apache Tika 统一解析 doc / docx / pdf / html / txt，保留表格结构（单独抽取表格为结构化文本，避免行列错位）
2. **数据清洗**：`DocumentCleaner` 责任链 —— 去首尾空白、丢弃空段、全角半角归一、剔除页眉页脚与页码、修复被硬换行拆断的句子
3. **双轨切分**：
   - **章节级**（供评审用）：按章节标题切分，粒度几百至几千字
   - **检索级**（供检索用）：300-500 字一块，10-20% 重叠
4. **向量化**：BGE-M3 生成向量，写入向量库（Milvus / Qdrant / pgvector）
5. **图谱构建**：LLM 抽取实体（项目、技术领域、学生、指导教师、竞赛、成果）与关系（指导、参与、获奖于、属于领域），写入 Neo4j
6. **社区摘要**：Louvain 社区检测 + 社区摘要，支撑全局性提问（GraphRAG 核心）

**输出**：向量索引 + 知识图谱 + 社区摘要。

---

### 阶段二：学生提交 —— 申报填写与智能预检

**状态流转**：`draft` → `submitted`

**步骤**：

1. 学生登录，填写项目信息（项目名、类型、简介、创新点、背景、意义、市场分析、关键技术）
2. 填写项目成员、指导教师
3. 上传计划书（docx / pdf）
4. **触发智能预检**（提交前自检，是本阶段核心）：
   - 文档解析 + 清洗（复用阶段一的能力组件）
   - 章节切分 → 与「应含章节清单」比对，检查**结构完整性**
   - 字段抽取 → 检查**必填信息齐全度**
   - 向量检索 → **相似度查重**（识别换说法的重复申报）
   - AIGC 检测 → **代写风险提示**（困惑度 + 文本统计特征）
5. **输出「申报书健康度报告」**：综合评分 + 问题清单 + 修改建议
6. 学生依据报告修改，确认提交

**设计要点**：预检**不阻断**提交，只提示。既保住学生自主性，又能显著降低后续驳回率。

---

### 阶段三：文档处理 —— 解析、清洗、章节切分

**状态流转**：`PENDING` → `PARSING` → `SPLITTING`

**步骤**：

1. **解析**：Tika 抽取正文段落 + 表格结构，得到结构化文档对象
2. **清洗**：`DocumentCleaner` 责任链处理
3. **章节切分**（两级策略）：
   - **规则召回**：正则匹配候选标题（`第X章`、`1.1`、`一、` 等），保证高召回
   - **模型精判**：CRF / BERT-CRF 对候选做序列标注，结合编号连续性、缩进、长度等特征，排除正文中误判的编号句
4. **权重确定**：AHP 层次分析法确定各章节权重（含一致性检验 CR < 0.1），替代硬编码等权

**输出**：章节列表（标题、层级、内容、字数、权重）。

---

### 阶段四：智能评审 —— 多智能体检索·辩论·共识

**状态流转**：`SPLITTING` → `RETRIEVING` → `AGENTS_REVIEWING` → `DEBATING` → `CONSENSUS`

**步骤**：

1. **知识检索**（`RETRIEVING`）
   对每个章节，从 GraphRAG 检索：
   - 该章节对应的**评审细则原文**
   - 历年优秀项目的**同类章节片段**（作为标杆参照）
   - 相关技术领域的历史项目
2. **多智能体并行评审**（`AGENTS_REVIEWING`）
   四个专家 Agent 并行工作，各自持有独立的评分维度与提示词：

   | Agent | 关注维度 |
   |---|---|
   | 技术专家 | 创新性、技术可行性 |
   | 市场专家 | 市场需求、商业模式 |
   | 财务专家 | 预算合理性、投入产出 |
   | 政策专家 | 合规性、政策导向 |

   各自输出：评分 + 打分理由 + **原文证据摘录（evidence）**
3. **交叉辩论**（`DEBATING`）
   - 第 1 轮：各 Agent 展示意见，看到彼此判断
   - 第 2 轮：针对分歧点互相质疑、修正
   - 全过程写入 `agent_debate_log`，供前端可视化回放
4. **共识汇总**（`CONSENSUS`）
   - 汇总 Agent 或加权投票机制输出各章节最终分数
   - 保留少数意见（分歧点单独标注）

**设计要点**：辩论轮次可配置（建议 2 轮起步，太多会显著增加成本）；每个 Agent 的独立意见必须留档，用于后续分歧分析。

---

### 阶段五：校验汇总 —— 证据溯源与等级判定

**状态流转**：`CONSENSUS` → `VERIFYING` → `SUMMARIZING` → `DONE`

**步骤**：

1. **证据溯源校验**（`VERIFYING`）
   逐条验证 AI 给出的 evidence 是否**真实存在于原文**：
   - 精确匹配 → 通过
   - 模糊匹配（容忍标点/空白差异）→ 通过并标注
   - 未匹配 → 判定为**疑似编造**，记录进 `evidence_verification`
   - 输出指标：**证据真实率**（可直接作为论文实验数据）
2. **置信度评估**
   对同一章节多次采样，计算评分方差；低置信度章节标记「建议人工重点复核」
3. **综合得分计算**（`SUMMARIZING`）
   - **必须使用加权平均**：`总分 = Σ(章节分 × 权重) / Σ权重`
   - 注意避免现有实现中"加权求和导致分数随章节数膨胀"的缺陷
4. **等级判定**：按阈值映射 A / B / C / D
5. **报告生成**：综合评述 + 亮点 + 主要问题 + 风险 + 分章节建议
6. **落库**：写入 `ai_review_task` / `ai_review_section` / `ai_review_report`

---

### 阶段六：人工复核与持续学习

**状态流转**：`DONE` → 人工裁定 → `approved` / `rejected`

**步骤**：

1. **结果呈现**（评审人）
   - 实时进度（SSE / WebSocket 推送，替代轮询）
   - 综合得分 + 等级 + 雷达图
   - 各章节得分与评语
   - **证据高亮**：点击结论跳转原文对应位置
   - **辩论回放**：查看各 Agent 的意见与分歧
   - 置信度标注：低置信处提示人工复核
2. **人工裁定**
   - 评审人可**修改** AI 的评分与评语
   - 做出最终结论：通过 / 驳回（附理由）
   - 推送站内通知给申请人
3. **偏好数据回流**（闭环关键）
   - 记录「AI 原版结论」与「人工修正后结论」为偏好对（chosen / rejected）
   - 写入 `preference_pair` 表
4. **持续学习**（离线，定期执行）
   - 累积偏好数据 → DPO 微调（Qwen + LoRA）
   - 评估新模型 → 上线替换
   - 形成「越用越懂本校评审标准」的正向循环
5. **数据洞察**（管理员）
   - 知识图谱可视化
   - 全局问答（"历年项目的主要短板是什么"）
   - 主题挖掘与趋势分析

## 三、状态机设计

```
PENDING          已创建任务
  ↓
PARSING          文档解析中
  ↓
SPLITTING        清洗与章节切分中
  ↓
RETRIEVING       知识检索中
  ↓
AGENTS_REVIEWING 多智能体评审中
  ↓
DEBATING         交叉辩论中
  ↓
CONSENSUS        共识汇总中
  ↓
VERIFYING        证据校验中
  ↓
SUMMARIZING      总评生成中
  ↓
DONE             完成
  ↓
FAILED           失败（任意阶段均可进入，需记录 error_msg）
```

> 说明：现有实现中的 `CLEANING` 状态为空坑位，本设计中清洗并入 `SPLITTING` 阶段，不再单列。

## 五、技术栈清单

| 能力 | 选型 | 说明 |
|---|---|---|
| 文档解析 | Apache Tika | 支持 doc / docx / pdf / html，解决现有 POI 仅支持 docx 的问题 |
| 文本清洗 | 自建 `DocumentCleaner` 责任链 | 收拢散落的清洗逻辑，可插拔 |
| 章节切分 | 正则召回 + CRF/BERT-CRF 精判 | 替代单条正则 |
| 权重确定 | AHP 层次分析法 | 含一致性检验 |
| 向量化 | BGE-M3 | 中文语义效果好 |
| 重排序 | BGE-Reranker | 提升检索精度 |
| 知识图谱 | Neo4j + Louvain + PageRank | GraphRAG 底座 |
| Agent 编排 | **LangChain4j** | 纯 Java 库，**无需升级 Spring Boot 3.2.0** |
| 工具协议 | MCP（Model Context Protocol） | 将系统能力暴露为 Agent 可调用工具 |
| 模型 | DeepSeek（在线）+ Qwen（本地/微调） | 多模型路由控成本 |
| 微调 | LoRA + DPO（LLaMA-Factory） | 偏好对齐 |
| 进度推送 | SSE / WebSocket | 替代 2 秒轮询 |
| 可观测 | Langfuse / OpenTelemetry | Agent 调用链路追踪 |

> **重要**：现有 `pom.xml` 为 Spring Boot **3.2.0**，而 Spring AI 1.1 需 3.5.x、2.0 需 Boot 4。故选型以 **LangChain4j** 为主，避免升级牵连 MyBatis、PageHelper、JJWT 等依赖。

## 六、创新点总结（答辩用）

| 序号 | 创新点 | 归属 |
|---|---|---|
| 1 | **多智能体协作评审**：四角色分工 + 交叉辩论 + 共识汇总 | 核心方法 |
| 2 | **GraphRAG 知识底座**：支持全局性提问，弥补传统向量 RAG 缺陷 | 关键技术 |
| 3 | **证据溯源与幻觉抑制**：逐条校验原文证据，输出「证据真实率」 | 可信性 |
| 4 | **人机协同持续学习**：人工修正数据回流，DPO 偏好对齐 | 闭环进化 |
| 5 | 提交前智能预检：结构完整性 + 查重 + 代写检测 | 事前预防 |
| 6 | Agent 辩论过程可视化 | 交互创新 |

### 可量化的实验指标

- **切分质量**：Pk / WindowDiff
- **评分一致性**：与人工评分的 Pearson r、Cohen's Kappa、MAE、RMSE
- **证据真实率**：溯源校验通过比例
- **稳定性**：同一文档多次运行的标准差
- **效率提升**：单份申报书评审耗时对比（人工 vs 系统）
- **显著性**：Wilcoxon 符号秩检验 / 配对 t 检验（p < 0.05）

## 七、落地顺序建议

| 阶段 | 任务 | 产出 | 前置条件 |
|---|---|---|---|
| **第一步** | 修复地基：启用 `@EnableAsync` + 线程池；重构状态机；修正总分算法；补表格解析 | 现有 AI 评审流程正确可用 | 无 |
| **第二步** | 统一文档处理：接入 Tika，建 `DocumentCleaner` 责任链，双轨切分 | 文档处理能力组件 | 第一步 |
| **第三步** | 多智能体编排：四专家 Agent + 辩论引擎 + 共识汇总 | 核心创新落地 | 第二步 |
| **第四步** | GraphRAG：图谱构建 + 检索接入 | 知识底座 | 第二步 |
| **第五步** | 校验与报告：证据溯源 + 置信度 + 前端可视化 | 完整评审体验 | 第三、四步 |
| **第六步** | 持续学习：偏好数据回流 + DPO 微调 | 闭环 | 第五步 + 足量数据 |
| **第七步** | 数据洞察：图谱可视化 + 全局问答 + 趋势分析 | 管理端增强 | 第四步 |

> **关键提醒**：第一步必须先做。异步未生效、总分算法错误这两项会直接导致后续所有工作建立在错误基础上。
